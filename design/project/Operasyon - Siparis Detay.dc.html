Detay sözleşmesi (kodlayan ajan için)
  • Tam sayfa, tek kayıt → /admin/siparisler/<no>. Listedeki diyalog yalnız bakış: künye + kalan tahsilat + "Detayı aç →". Sol kolon kaydı (künye → kalemler → para → zaman → kararlar), sağ ray bağlamı (müşteri/vade, teslimat/kanıt, bağlar) taşır.
  • Türetilmiş alan yazılmaz → ödeme durumu, satır tutarı, kalan, iade tutarı hesaplanır; operatör yalnız onaylar. Sipariş anındaki birim fiyat sabitlenmiştir, fiyat listesi değişince geçmişe işlemez.
  • İzin modeli → yalnız izinli geçiş listelenir (pasif buton yok). Teslimden sonra kısmi karşılama sunulmaz, iadeye dönüşür; teslimden önce iade sunulmaz.
  • Kısmi karşılama ≠ iade → aynı kalem-seçici, farklı sonuç: karşılanmayan adet tutardan düşer (tahsil edildiyse iadeye devrolur); iade ayrıca malın akıbetini (rafa döndü / imha / müşteride kaldı) ve para yolunu (karta / nakit / hesaba alacak) kaydeder — akıbet stok hareketini, yol Para'yı besler.
  • Maliyet/kâr → yalnız Kararlar bloğunda, yönetici rolünde, kapalı başlar. Künyede ve rayda hiç geçmez; operatör rolünde blok render edilmez. Dönem marjı Raporlar'da kalır.
  • Yoğun/sade aynı iskelet → bölüm sırası değişmez; verisi olmayan blok (talep, iade, kanıt, vade) hiç çizilmez, zaman çizelgesi tek satıra iner. Atlanan durum adımı gri noktayla görünür kalır ("atlandı — limit içinde").
  • Sınırlar → gün rotası Rotalar'da, hazırlık ve parti seçimi Depo'da, kuryenin listesi Kurye'de, müşteri metni bildirim şablonlarında. Bu ekran tek siparişe kurye atar, gün planlamaz.
